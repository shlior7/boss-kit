# boss-deck

A quiet, read-only Claude Code pane for a boss session. It shows:

- **review ↗ <date>**: the latest review page, from this boss's `review.txt`
- **inbox**: unread input from outside the session (today, boss mail), one line per message with its kind in yellow; shown only while something is unread, and every prompt carries one context line naming it
- **now**: this boss's one next action, from its `next.txt`
- **what needs you**: blocked workers, idle workers whose dispatch has no watcher, stale watchers, red CI, and PRs that are approved and green
- **bosses**: this project's live bosses from the registry, this one first: `main` and its domain bosses (a `Domain: <name>` line in `CLAUDE.local.md`), `(this)` on the current one, `N working · M for you`, and the heartbeat age once it is stale. A domain boss's pane covers only its sidebar folder (`Folder: <tag>` in `CLAUDE.local.md`, else the domain name): its workspaces, their watchers and PRs, no PR-only rows. Press one for its next line, the first lines of its domain state file, when it was last seen, and `open workspace ↗`
- **workers**: one row per dispatched Paradev workspace: name, its PR joined by branch (or `—`), then stage · time in stage · note. Active first (your move, boss checking, working, blocked), then idle and dim (in review, idle without a DONE, done today: merged or retired today, at most 5); the header reads `N active · M idle`. Time in stage comes from the boss's `events.jsonl` (`bin/boss-event`). A tracked PR no workspace owns is an idle row with its tag as the name and its status (green approved, blue waiting on a reviewer, yellow conflict, red CI, grey draft; an approved, green PR without proof reads **no proof** in yellow); PRs idle for 10+ days fold into one line. Press a row (or its key, 1–9) to expand it: the workspace's timed stage history and next step, its PR's title, CI, mergeability, reviews, size, branch and head, its worker's task progress (`tasks 3 of 5 · now …`, from `<worktree>/.boss/status.json`) and the last two lines of its `.boss/notes.md`, what it is doing, context use, and one link row: proof (`page ↗`, `demo ↗`, `artifact ↗`), `open workspace ↗`, `open on GitHub ↗`
- **messages**: each `superset terminals send --text` the boss runs is logged as that workspace's `msg` event (key-only sends are not), for the worker's FROM BOSS
- **footer**: a tracker summary (`tracker: N mine · N P0/P1 · N in progress`) only when one is synced, and **N new shared lessons** when shared lessons were added since this boss's last session

The boss view loads only in a session whose working directory has a `CLAUDE.local.md` with `# Boss workspace <id>`, where `<id>` is that session's `$SUPERSET_WORKSPACE_ID` (a bare `# Boss workspace` matches any session). A copy of the file in another worktree, or another workspace on the same checkout, gets no boss pane and sends no heartbeat (only the worker view below, when it was dispatched). Data comes from `bin/boss-deck-data.py` under `$BOSS_KIT_HOME` (default `~/.claude/boss-kit`). It reads project data from `$BOSS_HOME` (default `~/.claude/boss`), and each refresh is this boss's heartbeat. It refreshes every 60 s and right after the boss dispatches, merges or comments. `/boss-deck` opens and refreshes it.

**Worker view.** In a session that is not the boss but whose workspace has a dispatch row in some project's ledger, the same pane shows that worker's own status: a `WORKER <workspace> · <task>` header with `boss: <project>`; its goal, PR (by the current branch) and state (working or idle, time in stage, `now:` its latest tool call or reply line); **tasks** `N of M done` from its own task-list tool calls; **delivered** (pushed commits and its stage events, newest first); **notes** (the last lines of `.boss/notes.md`); **from boss** (`N new` since its last turn); a warning line (context 60%+, behind its base, CI red, idle without a DONE comment); and a link row (proof, `PR ↗`, `boss ↗`, context %, refresh age). It writes its task progress to `<worktree>/.boss/status.json` for the boss's row and keeps `.boss/` in `.git/info/exclude`. No dispatch row, no pane.
