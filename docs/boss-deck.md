# boss-deck

The pane ships in the `boss` plugin (`hooks/register.tsx`, loaded by `hooks/hooks.json`); one `/plugin install boss@boss-kit` gives it. A quiet, read-only Claude Code pane for a boss session. It shows:

- **review ↗ <date>**: the latest review page, from this boss's `review.txt`
- **inbox**: unread input from outside the session (today, boss mail), one line per message with its kind in yellow; shown only while something is unread, and every prompt carries one context line naming it
- **now**: this boss's one next action, from its `next.txt`
- **what needs you**: blocked workers, idle workers whose dispatch has no watcher, stale watchers, red CI, and PRs that are approved and green
- **bosses**: this project's live bosses from the registry, this one first: `main` and its domain bosses (a `Domain: <name>` line in `CLAUDE.local.md`), `(this)` on the current one, `N working · M for you`, and the heartbeat age once it is stale. A domain boss's pane covers only its sidebar folder (`Folder: <tag>` in `CLAUDE.local.md`, else the domain name): its workspaces, their watchers and PRs, no PR-only rows. Press one for its next line, the first lines of its domain state file, when it was last seen, and `open workspace ↗`. This boss's own workspace is never listed as a worker; its other agent terminals (research and ops sessions) are `sessions` lines in its expanded row: terminal title, agent state, age, and the ledger task text when a row names that terminal
- **workers**: one row per dispatched workspace (a worker on the boss's host): name, its PR joined by branch (or `—`), then stage · time in stage · note. Active first (your move, **done · waiting on you** — the boss logged `checked` or `ready`, yet the PR stays a draft or there is none — boss checking, working, blocked), then idle and dim (in review, idle without a DONE, done today: merged or retired today, at most 5); the header reads `N active · M idle`. Time in stage comes from the boss's `events.jsonl` (`bin/boss-event`). A tracked PR no workspace owns is an idle row with its tag as the name and its status (green approved, blue waiting on a reviewer, yellow conflict, red CI, grey draft; an approved, green PR without proof reads **no proof** in yellow); PRs idle for 10+ days fold into one line. Press a row (or its key, 1–9) to expand it: the workspace's timed stage history and next step, its PR's title, CI, mergeability, reviews, size, branch and head, its worker's task progress (`tasks 3 of 5 · now …`, from `<worktree>/.boss-worker/status.json`) and the last two lines of its `.boss-worker/notes.md`, what it is doing, context use, and one link row: proof (`page ↗`, `demo ↗`, `artifact ↗`), `open workspace ↗`, `open on GitHub ↗`
- **drift and a stale kit**: a PR behind its base (`3 behind main`, yellow) or in conflict with it (`conflicts with main`, red) carries that note in its workers row and an expanded `drift` line; when the kit on disk (its git HEAD) differs from the one the pane loaded, an attention line `kit updated · restart: claude --continue` shows until the session is restarted (`bin/boss-kit-update` updates the kit and mails every live boss)
- **messages**: each `boss-host send` the boss runs is logged as that workspace's `msg` event, for the worker's FROM BOSS
- **footer**: a tracker summary (`tracker: N mine · N P0/P1 · N in progress`) only when one is synced, and **N new shared lessons** when shared lessons were added since this boss's last session

The boss view loads only in a session whose worktree has a `CLAUDE.local.md` at its top (`git rev-parse --show-toplevel`, where `bin/bosskit.py` reads it too, so a session started in a subfolder finds it; outside git, the session's directory) with `# Boss workspace <id>`, where `<id>` is that session's id on its host (`boss-host session`, which the pane asks; it reads no env itself) (a bare `# Boss workspace` matches any session). A copy of the file in another worktree, or another workspace on the same checkout, gets no boss pane and sends no heartbeat (only the worker view below, when it was dispatched). Data comes from `bin/boss-deck-data.py` under `$BOSS_KIT_HOME` (default `~/.boss-kit`, or `~/.claude/boss-kit` until `bin/boss-migrate` moves it). It reads project data from `$BOSS_HOME` (default `~/.boss`), and each refresh is this boss's heartbeat. It refreshes every 60 s and right after the boss dispatches, merges or comments. `/boss-deck` opens and refreshes it; it is registered in every session, and outside a boss or a dispatched worker it answers "Not a boss here: run /boss to set one up." A session that is not the boss re-reads `CLAUDE.local.md` on each 60 s tick, so one that `/boss onboard` makes the boss mid-session gets the pane without a restart, host session id or not. From then on it draws only the boss view, titled Boss: a worker refresh still in flight when it switched is dropped.

**Worker view.** In a session that is not the boss but whose workspace has a dispatch row in some project's ledger, the same pane shows that worker's own status: a `WORKER <workspace> · <task>` header with `boss: <project>`; its goal, PR (by the current branch) and state (working or idle, time in stage, `now:` its latest tool call or reply line); **tasks** `N of M done` from its own task-list tool calls; **delivered** (pushed commits and its stage events, newest first); **notes** (the last lines of `.boss-worker/notes.md`); **from boss** (`N new` since its last turn); a warning line (context 60%+, behind its base, CI red, idle without a DONE comment, `kit updated · restart: claude --continue`); and a link row (proof, `PR ↗`, `boss ↗`, context %, refresh age). It writes its task progress to `<worktree>/.boss-worker/status.json` for the boss's row and keeps `.boss-worker/` in `.git/info/exclude`. No dispatch row, no pane.
