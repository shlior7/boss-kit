# Ledger and memory (BOSS-template.md section 10, full wording)

The template keeps each rule of section 10 as one short line; this is the full wording, with its examples and steps. Read it before your first ledger write in a session.

Keep the boss ledger in the project's `ledger.md` (stack shape, dispatched tasks, pending decisions, dated reminders); update it on every dispatch, merge and decision. The project's bosses share it. Log every dispatch as one row in a `## Dispatches <date>` table (Date / Task / Workspace / Model / Status / Proof / Boss), with your boss id in Boss. The pane reads each workspace's task from there, and its proof links from the Proof column once the worker reports. Rows without a Boss column belong to every boss of the project. Durable lessons go in the lessons files (section 14), not the ledger. Re-verify any ledger fact before acting on it. `boss-janitor ledger` keeps the file small: it moves finished rows of closed workspaces and dated log entries older than 7 days to `ledger-archive/<YYYY-MM>.md` and cuts cells over 500 characters, the full line going to the archive; look there for anything older.
